# P6：超级终端积木

> 优先级 6 · 规模 XL（≥ 8 周） · 前置：P1（作品库）、P4（传感器数据协议）
> · 全部方案中工程量与测试成本最高，最后启动；开工前先做权限调研 spike

## 目标

跨 HarmonyOS 设备的分布式积木：手机当游戏手柄、手表当传感器、
智慧屏当第二舞台。**没有任何积木语言能做**，是 Tesslo 的旗舰差异点。

## 现状与锚点

- 组网与发现基于分布式软总线（`@ohos.distributedDeviceManager` /
  DistributedServiceKit）。
- P4 传感器协议已预留 `source: local|remote` 字段，远程输入复用
  同一格式。
- 需要常态化 ≥ 2 台真机（平板 + 手机）测试环境。

## 技术设计

### 拓扑与角色

- **舞台端**（一台）：Tesslo 播放模式，运行作品 + 接收输入
- **输入端**（N 台）：Tesslo 输入模式（薄壳页面），仅采集传感器 /
  按键 / 麦克风能量并上报

### 协议（复用 P4 格式，加版本号）

```json
{"proto": 1, "source": "remote", "device": "phone-1",
 "type": "sensor", "sensor": "accel", "x": 0.1, "y": 0, "z": 0.9,
 "ts": 1763000000000}
```

- 协议带版本号：两端 Tesslo 版本不一致时低版本拒绝连接并提示升级
- 语义约定：**事件至多一次、reporter 最新值**（不做重放 / 重传）
- 断连语义：设备离线触发 hat 事件（"当设备离开"），积木可感知兜底

### 积木（舞台端扩展 tesslo-distributed）

- hat：当任一设备被晃动 / 被按下方向键 / 加入 / 离开时
- reporter：某设备的倾斜角 / 按键状态、在线设备列表、设备计数

### 权限与分发

- 分布式权限（`ohos.permission.DISTRIBUTED_DATASYNC` 等）申请时机
  与文案；上架审核口径提前调研（开工前 30 分钟 spike，
  结论不过关则调整形态，如同账号接续方案）
- 首次配对全流程 ≤ 3 步（发现 → 确认 → 开始）

## 任务拆解

- [ ] 权限与审核口径调研 spike（过不了则调整方案形态再立项）
- [ ] 分布式组网与设备发现真机跑通（舞台 + 输入端握手）
- [ ] 协议 v1 定义 + 与 P4 格式对齐 + 版本拒绝逻辑
- [ ] 输入端薄壳页（传感器采集 + 上报）
- [ ] 舞台端扩展：事件类积木 + 手柄按键输入
- [ ] 断连事件与兜底演示样例（双人小游戏）
- [ ] reporter 类远程传感器（手表心率等）与在线设备管理积木
- [ ] 舞台镜像到智慧屏（continuation / 流式投屏，最后做）

## 验收标准

- [ ] 平板运行作品 + 手机作手柄，操控手感延迟 < 100ms
- [ ] 手机飞行模式离线时舞台端收到"设备离开"事件，作品可兜底
- [ ] 首次配对全流程 ≤ 3 步
- [ ] 两端版本不一致时拒绝连接并提示升级（无未定义行为）

## 风险与备注

- **测试成本是最大风险**：常态化双真机矩阵（版本 × 机型），
  CI 之外建固定手动回归清单
- 与 P4 的协议耦合：P4 后续改动需同步本方案 `proto` 版本
