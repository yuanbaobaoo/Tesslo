# 迭代路线图

> 状态：v1.4（2026-11）· 编号 P1–P6，N 即优先级 · 各迭代完整方案见 [docs/plans/](plans/README.md)

Tesslo v1.0 完成了"Scratch 在 HarmonyOS 上的完整移植"。下一阶段的定位转变：
**从"Scratch 的移植"走向"Scratch 做不到的创作工具"**。

差异化总原则：做 Scratch 官方因设计哲学或平台形态**不做的事**（设备原生
能力、端侧 AI、离线、积木→代码阶梯、触屏优先），而不是在官方已有的
事情上竞争。

## 1. 现状锚点

方案均锚定在仓库现有事实上，避免空中楼阁：

| 事实 | 位置 | 对迭代的影响 |
| --- | --- | --- |
| 平台能力桥全部走回环 TCP，无 javaScriptProxy | `entry/ets/ble`、`entry/ets/assets`、`Ports.ets`（20111/20113/20114） | 新桥（传感器、AI、作品库）沿用同一模式，架构一致 |
| 扩展库已启用 faceSensing / text2speech / translate / videoSensing | `scratch-gui/src/lib/libraries/extensions/index.jsx` | 端侧 AI 的起点是"修复 + 替换后端"，不是从零建 |
| GUI 为 `canSave={false}`，项目只能下载 .sb3 | `apps/host/ohos/web/src/index.jsx` | 作品管理需要先建"本地作品库"基础层 |
| scratch-gui 支持 `isPlayerOnly` 播放模式 | `scratch-gui/src/components/gui/gui.jsx` | 单文件 HTML 导出可复用现成播放态 |
| 素材 1328 个文件全部离线，AssetServer 本地服务 | `apps/host/ohos/assets/fetched` | 素材本土化 = 元数据中文化 + 增量主题包 |
| deviceTypes 为 tablet / 2in1 | `entry/src/main/module.json5` | 触屏优化有真实设备受众 |
| 已声明 INTERNET / BLUETOOTH / CAMERA / MICROPHONE | `module.json5` requestPermissions | 端侧语音的权限已就绪；传感器多免权限 |
| 上游 Scratch 3.x 进入维护期（4.0 为重写，2026 年内） | — | fork 漂移顾虑降低，可放手做深度定制 |

## 2. 迭代总览

六个迭代，编号即优先级；方案内不再分期，任务清单即执行顺序：

| 编号 | 方案 | 一句话定位 | 规模 | 前置 |
| --- | --- | --- | --- | --- |
| P1 | [作品管理](plans/P1-works.md) | 作品库 + 快照版本 + 一键导出单文件 HTML | L | 无 |
| P2 | [触屏交互](plans/P2-touch.md) | 单指完成全部核心编辑操作 | S–M | 无 |
| P3 | [积木-代码双视图](plans/P3-dual-view.md) | 积木旁看生成代码，运行高亮联动 | M–L | 无 |
| P4 | [端侧能力](plans/P4-ondevice.md) | 传感器积木 + 语音/视觉端侧化，离线可用 | L | 无 |
| P5 | [素材本土化](plans/P5-assets-l10n.md) | 素材中文化 + 中文搜索 + 本土主题包 | S–M | 无 |
| P6 | [超级终端积木](plans/P6-super-device.md) | 跨设备：手机手柄、手表传感器 | XL | P1、P4 |

规模口径（单人开发）：S ≤ 2 周，M = 2–4 周，L = 4–8 周，XL ≥ 8 周。

## 3. 依赖与并行

```text
P1 作品管理 ──→ P6 超级终端（作品库地基）
P4 端侧能力 ──→ P6 超级终端（传感器数据协议复用）
P2 触屏 / P3 双视图 / P5 素材：相互独立，可灵活插排
```

- **P1 → P2**：P1 先行（存储可靠是工具的信任底线）；P2 与任何方案
  无耦合，可在 P1 期间随时并行插入。
- **P5 编号靠后但可全程并行**：纯内容型工作（词条、索引、素材包），
  不占开发主线，碎片时间推进即可。
- **P6 最后做**：依赖 P1 与 P4 两层地基，且需常态化双真机测试；
  开工前先做分布式权限调研 spike，不过关则调整形态。

## 4. 横切原则

1. **模块化边界**：Tesslo 扩展积木走引擎 extension API（出于自有
   模块化考虑，非迁就上游）；宿主新能力一律回环服务模式
   （`Ports.ets` 统一登记），ArkWeb 与 ArkTS 之间不引入第二套桥机制。
2. **兼容引擎绞杀者管理**：内嵌 Scratch 系代码是 .sb3 兼容引擎
   （`packages/engine/scratch/`），非上游——无同步管道，上游仅作
   规格参考（跟踪其安全公告）；模块改动/重写在
   `docs/engine-rewrite.md` 登记，重写由兼容回归体系兜底。详见
   [IDE 架构](ide-architecture.md)。
3. **第三方协议**：新增第三方代码入库前过一遍协议（GPL 兼容性）。
4. **权限最小化**：沿用蓝牙"用到才申请"模型；传感器优先免权限 API；
   AI 类能力申请时机与扩展加载绑定，拒绝常驻采集。
5. **性能预算**：新增常驻服务内存 < 10MB；传感器事件流 ≤ 20Hz；
   端侧推理不阻塞 VM 主循环（异步回灌）。
6. **文档即决策记录**：本路线图随迭代滚动修订，方向级变更在文末
   变更记录登记原因。
